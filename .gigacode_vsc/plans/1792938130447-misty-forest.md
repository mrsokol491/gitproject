# Анализ: каких функций не хватает в Web-версии GitProject Workspace Hub

### CLI-скрипты (`bin/`) и их покрытие веб-API:

| CLI-скрипт | Веб-API | Статус |
|---|---|---|

| `git-project-update.sh` (публикация хаба) | `/api/hub_update.php` | ✅ Есть |
| `git-project-clone.sh` (клонирование с выбором хоста) | `/api/clone.php` | ✅ Есть |
| `git-project-remote.sh` (управление remote: list/add/remove) | `/api/projects_remotes.php`, `projects_remotes_add.php`, `projects_remotes_remove.php` | ✅ Есть |
| `git-project-remove.sh` (удаление проекта) | `/api/projects_remove.php` | ✅ Есть |
| `git-project-migrate.sh` (миграция между хостами) | — | ❌ Нет |
| `git-project-add-host.sh` (добавление нового Git-хоста) | — | ❌ Нет |
| `audit-project.sh` (аудиторский отчёт) | — | ❌ Нет |
| `git-project-sync-precheck.sh` (предпроверки перед sync) | — | ❌ Нет |
| `gitproject-sync-hub.sh` (мульти-push хаба) | — | ❌ Нет |

### Что уже работает в веб-интерфейсе (`public/index.php`):
- Таблица статусов Git-хостов (`/api/hosts.php`)
- Список проектов с метаданными (`/api/projects.php`)
- Синхронизация одного/всех проектов (`/api/sync.php`)
- Pull из конкретного remote
- Проверка и применение обновлений хаба (`/api/hub_update.php`)

## Недостающие функции (приоритеты)

### 🔴 Критичные (управление жизненным циклом проекта)

#### 1. Клонирование проекта (`git-project-clone.sh`)
**Что делает:** Интерактивный мастер клонирования с выбором хоста, owner, slug, локального имени, предложения добавить дополнительные remote.

**Что добавить в веб:**
- **API:** `POST /api/clone.php` — клонировать проект с выбранного хоста
- **UI:** Модальное окно/страница с формой:
  - Выбор хоста (dropdown из hosts.json)
  - Ввод owner и slug
  - Опционально: локальное имя каталога
  - Кнопка «Клонировать»
  - После клонирования: предложение добавить remote с других хостов

#### 2. Управление remote (`git-project-remote.sh`)
**Что делает:** `--list` (таблица remote + актуальность), `--add <domain>` (добавить remote), `--remove <remote>` (удалить remote).

**Что добавить в веб:**
- **API:** `GET /api/projects/:slug/remotes.php` — список remote с SHA/датой/статусом
- **API:** `POST /api/projects/:slug/remotes.php` — добавить remote (`--add <domain>`)
- **API:** `DELETE /api/projects/:slug/remotes/:remote.php` — удалить remote (`--remove`)
- **UI:** В карточке проекта — секция «Remote», таблица с SHA, датой, статусом (актуален/отстаёт); кнопки «Добавить» / «Удалить»

#### 3. Удаление проекта (`git-project-remove.sh`)
**Что делает:** Удаление локально / с конкретного хоста / со всех хостов с подтверждением через код.

**Что добавить в веб:**
- **API:** `DELETE /api/projects/:slug.php` — удаление проекта
  - Query param: `scope=local|host|all`
  - Для `host` / `all` — указание remote
- **UI:** Модальное окно подтверждения с вводом кода `DELETE-LOCAL` / `DELETE-ALL` / `DELETE-<HOST>`

---

### 🟡 Важные (мульти-хост операции)

#### 4. Миграция между хостами (`git-project-migrate.sh`)
**Что делает:** Показывает таблицу актуальности версий (local + все remote), миграция версии от источника к приёмнику с обработкой fast-forward / расхождения / пустого приёмника.

**Что добавить в веб:**
- **API:** `GET /api/projects/:slug/migrate.php` — таблица версий (local, origin, gitverse, ... с SHA, датой, статусом)
- **API:** `POST /api/projects/:slug/migrate.php` — выполнить миграцию (`source` + `target`)
- **UI:** Вкладка/модальное окно «Миграция» — таблица версий с цветовой индикацией (🟢 свежий / 🟡 отстаёт / 🔴 расходится), выбор «откуда» / «куда», кнопка «Мигрировать»

#### 5. Мульти-push хаба (`gitproject-sync-hub.sh`)
**Что делает:** Публикация самого хаба на все настроенные remote из .env.

**Что добавить в веб:**
- **API:** `POST /api/hub_multi_push.php` — мульти-push хаба на все remote
- **UI:** Кнопка «Мульти-push хаба» в секции статуса хаба (отдельно от обычного pull)

---

### 🟢 Полезные (инструменты)

#### 6. Добавление хоста (`git-project-add-host.sh`)
**Что делает:** Wizard добавления нового Git-хоста с выбором из каталога, вводом учётных данных, тестом подключения, записью в .env и hosts.json.

**Что добавить в веб:**
- **API:** `POST /api/hosts.php` (POST-обработка) — добавить хост
- **UI:** Кнопка «Добавить хост» в секции хостов → форма: выбор хоста из hosts.json, ввод user/token, тест подключения, сохранение

#### 7. Аудит проекта (`audit-project.sh`)
**Что делает:** Генерирует полный отчёт по проекту (файлы, коммиты, секреты) в `data/audits/`.

**Что добавить в веб:**
- **API:** `POST /api/projects/:slug/audit.php` — запустить аудит
- **API:** `GET /api/audits/:slug-*.txt` — скачать отчёт
- **UI:** Кнопка «Аудит» в карточке проекта → запуск → ссылка на скачивание отчёта

#### 8. Предпроверки перед синхронизацией (`git-project-sync-precheck.sh`)
**Что делает:** Проверка запрещённых файлов, качества markdown, composer/phpunit/phpstan, ветки master, конфликтов.

**Что добавить в веб:**
- **API:** `POST /api/projects/:slug/precheck.php` — запустить предпроверки
- **UI:** Кнопка «Предпроверка» рядом с кнопкой синхронизации → вывод результатов (OK / FAIL с деталями)
